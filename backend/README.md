# FresshShop backend (Medusa 2.22)

Copied from `Yuki-223/shopStore` (`medusa-dtc/apps/backend`, the official Medusa DTC starter with the shopStore
changes: 5 MB body limit for `POST /admin/products` and the product search index). From here on this copy is
developed independently — shopStore is only used as the source of the collected Metagenics data.

## Run locally

Requires Node.js ≥ 22.23 and pnpm 10.

```bash
cd backend
pnpm install
pnpm setup:local   # embedded PostgreSQL in .local/, migrations, admin user
pnpm start:local   # PostgreSQL + Medusa → http://localhost:9000/app

# in a second terminal, with the backend running:
pnpm import:metagenics                    # 229 products (add --sample for 3)
pnpm import:reviews                       # 20 collected review texts (2 products)
node scripts/verify-metagenics.mjs        # checks everything through the Store API
```

## Metagenics data

`scripts/import-metagenics.mjs` reads the storefront's `../src/lib/data/metagenics/catalog.json` and the images in
`../public/products/` (shopStore is not needed). Besides products, variants (`Size` / `Flavor` options), USD prices,
18 categories and the main images, it stores as metadata:

- variant: `size`, `flavor`, `subscriptions` (`[{ months, price, savePercent }]`), `source_available`
- product: `rating` (`{ value, count }`, 213 products), `product_line`, `form`, `is_bundle`, `health_categories`,
  `content`, `supplement_facts`, `directions`, `storage`, `cautions`, `warnings`, `faq`, `related`

Stock starts at 99 per variant (0 for the 4 products that were out of stock in the source) and is never reset on
re-runs. A US region (USD), a demo warehouse and a $10 demo shipping option are created if missing.

When reading variant metadata from the Store API, use `fields=+metadata,*variants,…` — an explicit field list such as
`handle,title,…` drops `variants.metadata`.

- The database lives in `backend/.local/postgres` (port 55433), secrets and the admin login in
  `backend/.local/config.json`. Both are git-ignored.
- `.env` is generated by `pnpm setup:local`. CORS allows the storefront on `http://localhost:3000`.
- Running as root (cloud containers) is handled automatically: PostgreSQL runs as the `postgres` user.

## Product reviews (`src/modules/review`)

Custom Medusa module with a `review` table (`product_id`, `author_name`, `location`, `rating` 1–5, `title`, `content`,
`source` = `collected` | `customer`, `status`, `published_at`). The migration is in `src/modules/review/migrations/`
and runs with `pnpm setup:local` (or `pnpm exec medusa db:migrate`).

| Route | Purpose |
|---|---|
| `GET /store/reviews?product_id=…&limit=10&offset=0` | approved reviews, newest first, plus `summary` |
| `POST /store/reviews` | `{ product_id, rating, author_name, title?, content }` → created review + new `summary` (auto-approved in this demo) |
| `GET /admin/reviews?product_id=&source=&status=` | all reviews for the store owner (admin login required) |
| `POST /admin/reviews` | bulk create `{ reviews: [...] }` keeping author, location and date (used by `pnpm import:reviews`) |

`summary` = the rating collected from the source site (`product.metadata.rating`, which already counts the collected
reviews) merged with approved reviews written by our customers.

## Browsing history (`src/modules/browsing-history`)

Custom Medusa module with a `browsing_history` table (`customer_id`, `product_id`, `viewed_at`; one row per customer
and product). Only the newest 100 products per customer are kept. The migration is in
`src/modules/browsing-history/migrations/` — after pulling, run `pnpm setup:local` (or `pnpm exec medusa db:migrate`).

All routes need a signed-in customer (bearer token) and only touch that customer's own history:

| Route | Purpose |
|---|---|
| `GET /store/customers/me/browsing-history?limit=100&offset=0` | viewed products, newest first |
| `POST /store/customers/me/browsing-history` | `{ items: [{ product_id, viewed_at? }] }` (1–100) — records a view, or merges a guest's history after sign-in; a product seen again keeps the later time |
| `DELETE /store/customers/me/browsing-history/:product_id` | removes one product |
| `DELETE /store/customers/me/browsing-history` | clears the history |

Guests' history is kept in the browser (`localStorage` key `freshshop-history`, storefront `src/lib/store/history.ts`)
and merged into the account when they sign in or create an account.
